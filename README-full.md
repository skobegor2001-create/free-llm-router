# Free LLM Router

Среда для агента: **бесплатные нейросети пяти провайдеров в одной цепочке** —
Groq, Cerebras, Gemini, OpenRouter и Mistral. Упёрлись в лимит или провайдер
лёг → запрос сам уходит следующему. Внутри — веб-чат и
**OpenAI-совместимый шлюз**, поэтому сюда подключается любой агент или SDK
без единой правки логики: меняется только `base_url`.

```
 ваш агент / LangChain / CrewAI / SDK OpenAI
                 │  base_url = http://localhost:8000/v1
                 ▼
        ┌──────────────────┐
        │  Free LLM Router │──► Groq → Cerebras → Gemini → OpenRouter → Mistral
        └──────────────────┘        (429 → следующая модель/провайдер)
```

## Веб-чат

`http://localhost:8000` — поле ввода, выбор модели (auto / провайдер / конкретная
модель), температура, живая цепочка провайдеров с их лимитами и паузами.
Ответ приходит потоком; в шапке сообщения видно, какая модель реально отвечала
и сколько это заняло.

Полезные ручки:

| Ручка | Что делает |
|---|---|
| `GET /api/status` | провайдеры, ключи, лимиты, паузы после 429 |
| `POST /api/reload` | перечитать `.env` без перезапуска |
| `GET /api/models` | живые списки моделей (`?provider=groq&force=true`) |
| `POST /api/chat` | потоковый NDJSON: `meta` → `delta` … → `done` |
| `GET /health` | проверка живости |

## Для агента: OpenAI-совместимый шлюз

```bash
pip install openai
export OPENAI_BASE_URL=http://localhost:8000/v1
export OPENAI_API_KEY=local          # ключ не проверяется — шлюз локальный
```

```python
from openai import OpenAI
client = OpenAI()

resp = client.chat.completions.create(
    model="auto",                     # автопереключение провайдеров
    messages=[{"role": "user", "content": "Привет! Кто ты?"}],
)
print(resp.choices[0].message.content, "| ответила:", resp.model)
```

### Как выбирать модель

| `model=` | Поведение |
|---|---|
| `auto` | цепочка из `.env` (`PROVIDER_ORDER`), фолбэк при лимитах |
| `groq::auto` | только Groq, первая доступная его модель (без фолбэка на других) |
| `groq::openai/gpt-oss-120b` | конкретная модель конкретного провайдера |
| `openai/gpt-oss-120b` | модель, известная роутеру, — провайдер определится сам |
| любое другое имя | попытка через OpenRouter (самый широкий каталог) |

Список всех доступных имён: `GET /v1/models`.

### Любой фреймворк

Всё, что умеет OpenAI API, подключается через эти два параметра:

```python
# LangChain
from langchain_openai import ChatOpenAI
llm = ChatOpenAI(base_url="http://localhost:8000/v1", api_key="local", model="auto")

# CrewAI / LlamaIndex / AutoGen / Continue / Cursor / Open WebUI — аналогично
```

Tool-calling поддерживается: шлюз передаёт `tools` провайдеру и возвращает
`tool_calls` как есть. Рабочий пример агента с инструментами (калькулятор, время,
HTTP) — в `examples/agent_demo.py`.

## Работа с файлами (PDF, DOCX, TXT)

Прикрепите файл скрепкой в чате (или перетащите в окно) — текст извлечётся
**локально**, на вашем компьютере, и уйдёт модели вместе с вопросом. Поэтому
работает со всеми пятью провайдерами, а не только с «мультимодальными».

| Формат | Что поддерживается |
|---|---|
| **PDF** | текстовый слой, постранично (`--- стр. N ---`), кириллица, метаданные; сканы без текста — понятная ошибка с советом про OCR |
| **DOCX** | абзацы + таблицы (строки через ` \| `) |
| **TXT/MD/CSV/JSON/YAML + код** | обычные текстовые форматы, автоопределение кодировки (UTF-8, cp1251, KOI8-R) |

Лимиты: до 6 файлов, 25 МБ на файл, 60 000 символов на файл и 120 000 на запрос
(середина длинного файла сокращается с пометкой). Старый `.doc` не читается —
пересохраните как `.docx` или PDF.

Для агентов то же самое — в OpenAI-совместимом запросе:

```python
client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Найди в договоре условия оплаты"}],
    extra_body={"files": [{"name": "dogovor.pdf", "text": extracted_text}]},  # текст уже извлечён
)
```

Ручка извлечения: `POST /api/extract?name=файл.pdf` (тело — байты файла),
ответ: `{kind, chars, pages, text, warning, metadata}`.

## Поиск по вашему SQLite-индексу PDF (RAG)

Среда понимает схему приложения **PDF AI** (`documents` + `chunks` с BLOB-эмбеддингами
qwen3-embedding:0.6b) — и вообще любую базу с текстом.

```env
INDEX_DB=%LOCALAPPDATA%\PDF_AI_Local\data\pdf_ai.sqlite3
```

Больше ничего обязательно: таблицы, колонки (`text`, `sha`, `page`, `part`),
размерность векторов и папка `data\pdfs` определяются сами.

### Как ищет

| Режим | Когда | Что делает |
|---|---|---|
| **semantic** | Ollama доступна и в базе есть векторы | считает косинусную близость вашего вектора к векторам чанков |
| **lexical** | Ollama нет, нет векторов или `INDEX_SEARCH=lexical` | FTS5 / LIKE по словам с грубым отсечением русских окончаний |
| **auto** (по умолчанию) | — | пробует semantic, при неудаче честно падает в lexical |

Вектор запроса считается **той же моделью**, что индексировала базу:
`INDEX_EMBED_MODEL` (по умолчанию `qwen3-embedding:0.6b`),
`INDEX_EMBED_URL` (по умолчанию `http://127.0.0.1:11434`). Векторы кешируются
в памяти на 2 минуты: 5 000 чанков × 1024 мер — **6 мс** на запрос (numpy)
или ~0,65 с без numpy.

Порог отсечения: `INDEX_MIN_SCORE` (по умолчанию 0.25).

### Источники и просмотр страницы

В ответе под текстом появляются чипы `📄 договор.pdf · стр. 3` — клик открывает
текст этой страницы из исходного PDF (`data\pdfs\<sha>.pdf`). В API это
`GET /api/index/page?sha=...&page=3`, а в `/v1` — служебное поле `x_sources`.

### Для агентов

```python
client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "какие санкции за просрочку?"}],
    extra_body={"use_index": True, "index_limit": 5},
)
```

База открывается **только на чтение** (`mode=ro`), в неё ничего не пишется.

## Как работает автопереключение

1. Кандидаты собираются по `PROVIDER_ORDER`, провайдеры без ключа пропускаются.
2. Перед стримом проверяется «пауза»: у каждой пары **провайдер+модель** она своя.
3. Ответ провайдера разбирается до первого токена:
   * **429 «per day»** → пара на паузе 15 минут, идём дальше;
   * **429 «per minute»** → пауза 20 секунд;
   * **401/403** → пауза на всего провайдера (проблема ключа);
   * **5xx / таймаут / обрыв** → короткая пауза и следующий кандидат.
4. Стрим начинается только после успешного первого чанка — поэтому браузер
   пользователя никогда не видит «полудохлый» ответ.
5. Если соединение оборвалось уже в середине — честно сообщается, что нужно
   повторить запрос (повтор переключится на следующего).

Лимиты у моделей одного провайдера обычно раздельные — поэтому 429 по одной
модели не блокирует остальные модели того же провайдера.

## Windows: что внутри установщика

`install.cmd` идёт по шагам (сообщения только ASCII — console-кодировка не важна):

1. **Файлы** — если запущен из архива, копирует всё в `%LOCALAPPDATA%\FreeLLMRouter`.
2. **Python** — `runtime\python.exe` (portable) → `python` из PATH → поиск в
   `%LOCALAPPDATA%\Programs\Python` → установка 3.12 через `winget` → понятная
   ошибка со ссылкой на python.org. Требуется 3.9+.
3. **Зависимости** — в portable уже установлены (проверка импортом, интернет не
   нужен); иначе `pip install -r requirements.txt`, при отсутствии pip — бутстрап
   `get-pip.py`.
4. **Конфиг** — `.env` из шаблона (существующий не перезаписывается).
5. **Ярлыки** — «Пуск → Free LLM Router» и на рабочем столе, с иконкой.
6. Предлагает вписать бесплатный ключ и сразу открывает чат в браузере.

Лаунчер (`launcher.cmd`) умеет: запустить/остановить/перезапустить сервер в фоне
без окна консоли, открыть чат, вписать ключи, показать живой статус провайдеров,
запустить `doctor.py`. Порт: `PORT` из `.env`, иначе 8000, а если занят — первый
свободный; фактический пишется в `%LOCALAPPDATA%\FreeLLMRouter\data\port.txt`.
Журнал сервера — `data\server.log`. Удаление — `uninstall.cmd` (с выбором,
удалять ли файлы и ключи).

## Инструменты и агенты (tools / function calling)

Шлюз полностью поддерживает OpenAI-протокол инструментов — можно подключать готовые
агентские клиенты (Cline, OpenCode, Continue, CrewAI, LangChain, Open WebUI).

```python
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="local")

tools = [{
    "type": "function",
    "function": {
        "name": "search_index",
        "description": "Найти фрагменты в базе PDF",
        "parameters": {"type": "object",
                       "properties": {"query": {"type": "string"}},
                       "required": ["query"]},
    },
}]

r = client.chat.completions.create(
    model="auto-tools",                 # только модели с поддержкой инструментов
    messages=[{"role": "user", "content": "Найди пени в договоре"}],
    tools=tools,
)
print(r.choices[0].finish_reason)       # tool_calls
print(r.choices[0].message.tool_calls)  # [id, type, function{name, arguments}]
```

Что поддерживается:

| | Поддержка |
|---|---|
| `tools` в запросе | да (передаются провайдеру как есть) |
| `tool_calls` в ответе | да, с `id`, `type: function`, JSON-аргументами |
| `finish_reason: tool_calls` | да, и в стриме, и без |
| Стриминг вызовов | да: кадры `index` + `id` + `type` + `function`, как в OpenAI |
| `role: "tool"` + `tool_call_id` в истории | пробрасывается без изменений |
| Модель не умеет инструменты | роутер ловит 400, запоминает пару и идёт к следующей |
| `model: "auto-tools"` | автовыбор **только** среди моделей с инструментами |
| `GET /api/tools` | кто умеет, кто уже отсеялся на практике |

Важное про бесплатные модели: tool calling есть не у всех. Groq и Cerebras на
`gpt-oss-120b` умеют; у Gemini Flash — умеют; у `:free` моделей OpenRouter
поддержка разная, поэтому OpenRouter помечен как «проверяем на деле»: первая же
модель, ответившая «инструменты не поддерживаются», запоминается и больше не
предлагается. Смотрите фактические данные: `GET /api/tools`.

Как подключить конкретный клиент:

- **Cline / Continue / OpenCode** — Base URL `http://localhost:8000/v1`,
  API key любой, модель `auto-tools`.
- **Open WebUI** — «Настройки → Подключения → OpenAI API», тот же адрес.
- **LangChain** — `ChatOpenAI(base_url="http://localhost:8000/v1", api_key="local", model="auto-tools")`.
- **CrewAI** — `LLM(model="auto-tools", base_url="http://localhost:8000/v1", api_key="local")`.

Бюджет: один агентский шаг = один запрос к провайдеру. Для агентов лучше
Cerebras (1 млн токенов в день) — Gemini при 5–15 запросах в минуту упрётся
на втором-третьем шаге.

## История чатов

Диалоги сохраняются автоматически и переживают перезапуск сервера, обновление
и переустановку программы. По умолчанию база лежит **вне** папки программы:

| Система | Где база |
|---|---|
| Windows | `%LOCALAPPDATA%\FreeLLMRouter\data\chats.db` |
| Портативная версия | `<папка программы>\data\chats.db` |
| Своё место | `CHAT_DB=D:\мои\chats.db` в `.env` |

В левой панели — карточка **«История»**: список диалогов (свежие сверху) с датой,
числом сообщений и значком 📎, если к диалогу приложены файлы. Что умеет:

- **открыть** — клик по диалогу восстанавливает всю переписку, включая файлы
  (текст приложенных файлов хранится рядом с диалогом, поэтому «Продолжить»
  и вопросы по документу работают и на следующий день);
- **поиск** — по заголовкам и по тексту всех сообщений;
- **переименовать** — двойной клик по названию;
- **удалить** — крестик при наведении (с подтверждением);
- **выгрузить / загрузить** — вся история одним JSON: бэкап или перенос на другую машину.

Что важно знать:

- **«Продолжить» после перезагрузки** дописывает текст в тот же ответ модели,
  а не создаёт рядом второй — история остаётся чистой.
- **Файлы** хранятся до 150 000 символов на файл и 400 000 на диалог
  (это примерно 100–150 страниц). Более крупный файл в диалоге не сохранится —
  интерфейс предупредит, и его нужно будет приложить заново.
- **Удаление программы** историю не стирает: при удалении она спрашивается
  отдельным вопросом, а тихая деинсталляция базу не трогает.
- Ничего не отправляется в сеть: база — обычный SQLite-файл на этой машине.

Ручки:

| Ручка | Что делает |
|---|---|
| `GET /api/chats?q=` | список диалогов + поиск |
| `GET /api/chats/{id}` | диалог целиком (сообщения, метаданные, файлы) |
| `POST /api/chats/{id}/rename` | переименовать `{title}` |
| `DELETE /api/chats/{id}` | удалить диалог |
| `GET /api/chats/export/json` | скачать всю историю |
| `POST /api/chats/import` | загрузить JSON обратно |

Сервер сам ведёт историю: интерфейс присылает `chat_id`, сервер сохраняет вопрос
и дописывает ответ в процессе стрима (не чаще раза в 1,5 с — поток не тормозит).
Если `chat_id` не передан (шлюз `/v1`, агенты) — история не ведётся.
