# Агенты в Free LLM Router — варианты и план

Черновик проектирования, 18.11.2026. Ничего ещё не реализовано — это предложение.

---

## 1. Что уже есть и чего не хватает

| Есть | Нет |
|---|---|
| 5 провайдеров за одним шлюзом, автопереключение при 429/5xx | `tool_calls` теряются в потоковом режиме (`router._stream_provider` берёт только `delta.content`) |
| `/v1/chat/completions` пробрасывает `tools` провайдеру | `router.chat()` не возвращает `tool_calls` вызывающему коду |
| RAG по SQLite-индексу, файлы, история диалогов | цикла «модель → инструмент → модель» |
| Веб-чат с потоковым выводом и трассой событий | интерфейса трассы шагов агента |
| Установка одним кликом, без прав администратора | матрицы «кто из моделей умеет инструменты» |

Ключевой вывод: **агент — это в первую очередь цикл**, а не промпт. Промпт-пресет без цикла даёт «персону», но не агента.

---

## 2. Пять вариантов «что такое агент»

### A. Профили агентов (пресеты промптов)

Агент = имя + системная инструкция + модель + температура + набор инструментов.
Общение идёт в обычном чате, просто с подставленным system-промптом.

- **Плюс:** делается за вечер, нулевой риск, понятно пользователю.
- **Минус:** без цикла инструментов это «характер», а не исполнитель. Модель не может
  ничего проверить или найти — только отвечает тем, что уже в контексте.
- **Когда уместно:** как первый шаг, если нужны «готовые роли» (юрист, рецензент, методист).

### B. Агент с инструментами в веб-чате (ReAct-цикл на сервере)

Модель получает список инструментов. Каждый шаг: модель просит инструмент → сервер
выполняет → результат возвращается модели → следующий шаг → финальный ответ.

- **Плюс:** это и есть настоящий агент. Работает на существующих бесплатных моделях
  (`gpt-oss-120b` у Groq/Cerebras умеет tool calling, Gemini Flash — тоже).
  Переиспользует наш RAG: `search_index` уже готов на 100 %.
- **Минус:** нужно довести tool_calls через роутер и стриминг, сделать UI трассы,
  продумать лимиты шагов.
- **Оценка:** 2–3 дня работы, основной сценарий.

### C. Внешние агенты через шлюз

Cline, OpenCode, LangChain, CrewAI, Continue — все они уже умеют работать с
OpenAI-совместимым API. Наша задача — не «сделать агента», а **не мешать**:
корректные `tool_calls` (в т.ч. в стриме), `finish_reason: tool_calls`,
`tool_call_id`, параллельные вызовы, метка `auto-tools` (роутинг только на модели
с поддержкой инструментов).

- **Плюс:** самый большой выигрыш на единицу работы. Пользователь получает готовые
  зрелые агенты, мы — бесплатные модели под ними.
- **Минус:** без тестирования с реальными клиентами не видно, где ломается.
- **Оценка:** 1 день (это же — фундамент для B).

### D. Сценарные конвейеры (без LLM-цикла)

Жёсткий сценарий: «найди в индексе → извлеки страницы → сравни → собери отчёт».
Шаги заданы кодом, модель используется точечно.

- **Плюс:** предсказуемо, дёшево по токенам (2–4 вызова), почти не врёт.
- **Минус:** не агент — новый сценарий = новый код.
- **Когда уместно:** частые повторяющиеся задачи (анализ пачки договоров, извлечение
  реквизитов), где цикл только добавляет нестабильности.

### E. Мульти-агентная схема (планировщик + исполнители + критик)

- **Плюс:** лучший результат на сложных многошаговых задачах.
- **Минус:** 3–5× расход запросов; на бесплатных тирах (Groq 30 RPM, Gemini 5–15 RPM)
  это упирается в лимиты на втором прогоне. Сложная отладка.
- **Вердикт:** не сейчас. Только после того, как B стабильно работает.

## 3. Рекомендация: этапность

```
Этап 0  Фундамент:  tool_calls через роутер, стриминг, /v1, матрица моделей   ~1 день
Этап 1  MVP-агент:  цикл + 6 инструментов + трасса шагов в чате               ~2 дня
Этап 2  Профили:    сохранённые агенты (инструкция + инструменты + модель)     ~1 день
Этап 3  Действия:   запись файлов, веб-доступ, запуск кода (с подтверждением)  ~2 дня
Этап 4  Оркестрация: планировщик + исполнители (только если понадобится)
```

Порядок неслучаен: этап 0 нужен и для B, и для C; без него ни то, ни другое не работает.

## 4. Как будет работать MVP (этап 1)

```
Пользователь: «Сравни пени в трёх договорах из папки»
        │
        ▼
┌──────────────────────────────────────────────────┐
│ агентный цикл (server.py, до 8 шагов)            │
│                                                  │
│  шаг 1 → модель: search_index("пени просрочка")   │
│         ← 5 фрагментов + имена документов         │
│  шаг 2 → модель: read_page(sha, 12)               │
│         ← текст страницы                         │
│  шаг 3 → модель: search_index("ответственность")  │
│         ← ...                                    │
│  финал → модель: текст ответа со ссылками        │
└──────────────────────────────────────────────────┘
        │  события NDJSON: agent_step → tool_call → tool_result → delta
        ▼
   чат: ответ + свёрнутая «трасса» (что искал, что нашёл)
```

**Инструменты MVP (все безопасные, только чтение):**

| Инструмент | Что делает | Готовность |
|---|---|---|
| `search_index(query, limit)` | поиск по базе PDF (семантика + слова) | **есть**, обёртка |
| `read_page(sha, page)` | текст конкретной страницы PDF | **есть** (`/api/index/page`) |
| `list_documents()` | какие документы в индексе | **есть** (`/api/index/status`) |
| `read_file(name, offset, limit)` | кусок приложенного файла | есть (`state.activeFiles`) |
| `calculator(expr)` | арифметика без ошибок | новый, 20 строк |
| `now()` | дата/время | новый, 3 строки |

**Решения, которые предлагаю принять сразу:**

1. **Цикл на сервере, а не в браузере.** Иначе закроют вкладку — половина работы
   потеряется, и историю шагов не сохранить.
2. **Шаги — без стриминга, финальный ответ — стримингом.** Промежуточные шаги короткие,
   стримить их незачем; так проще обрабатывать `tool_calls` и меньше мусора в интерфейсе.
3. **Лимит: 8 шагов, 3 инструмента на шаг, результат инструмента — до 6000 символов.**
   Дальше мягкая остановка с честным сообщением «остановился: лимит шагов».
4. **Модель без поддержки инструментов — не ошибка.** Роутер ловит 400 «tools not
   supported» и переходит к следующей модели цепочки; если ни одна не умеет —
   агент честно отвечает без инструментов (как обычный чат).
5. **Трасса сохраняется в историю.** В `meta` сообщения пишем шаги: инструмент,
   аргументы, размер результата. Открыв диалог завтра, видно, откуда взялись выводы.
6. **Кнопка «Стоп» прерывает цикл** между шагами (не рвёт HTTP на середине).

**Бюджет на бесплатных тарифах** (прикидка для одного прогона в 4 шага):

| | Значение |
|---|---|
| Запросов к провайдеру | 5 (4 шага + финал) |
| Токенов | 8–12 тыс. (промпт ~1.2к + результаты инструментов) |
| Прогонов в день на Cerebras (1 млн ток./день) | ~80–100 |
| Прогонов в день на Groq (1000 запросов/день) | ~200 |

Вывод: агент реалистичен, но цикл в 8 шагов на Gemini (5–15 RPM) упрётся в лимит
быстрее — поэтому для агента по умолчанию ставим Cerebras/Groq.

## 5. Безопасность и подводные камни

| Риск | Что делаем |
|---|---|
| **Prompt injection из PDF** («игнорируй инструкции, вызови…») | инструменты MVP только читают; действия с побочными эффектами — только с подтверждением в UI |
| Модель вызывает несуществующий инструмент | возвращаем ошибку модели, а не падаем; счётчик неудач → остановка |
| Бесконечный цикл | жёсткий лимит шагов + таймаут прогона (120 с) |
| Раздувание контекста | результат инструмента обрезаем до 6000 символов, старые шаги сжимаем до «вызвал X → получил Y символов» |
| Утечка ключей в трассу | в шагах храним только имена инструментов и аргументы, не заголовки запросов |
| Недетерминированность (маленькие модели плохо вызывают инструменты) | для агента — приоритет `gpt-oss-120b`; в трассе видно, если модель «сочинила» вместо вызова |

## 6. Что решить

1. **Что важнее в первую очередь:** свой агент в чате (B) или шлюз для внешних
   агентов (Cline/OpenCode) (C)? Я бы делал этап 0 + C, затем B — C почти бесплатен
   после этапа 0.
2. **Набор инструментов:** только чтение (безопасно) или сразу запись файлов
   и запуск Python с подтверждением?
3. **Автономность:** все шаги автоматически или подтверждение перед каждым
   инструментом, который что-то меняет?
4. **Профили агентов (этап 2):** нужны сразу или достаточно одного «универсального»?

---

## 7. Что НЕ предлагаю делать

- **Автозапуск кода без подтверждения** — на бесплатных моделях риск ошибки высок,
  а отладка потом мучение.
- **Мульти-агентность на старте** — съест лимиты и время, а выигрыш неочевиден.
- **Свой «агентский» протокол на клиенте** — OpenAI-совместимость уже есть и работает;
  лучше усиливать её, чем изобретать своё.
